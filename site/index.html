The shift

Most of the work happens before the code.

Vibe coding skips straight to the part Claude is fastest at. Frontier moves your time to the parts only you can do: deciding what to build and checking what got built.

Without a method

  1. Prompt
  2. 400 lines of code
  3. Something breaks
  4. Prompt again

Every fix starts from a guess.

With Frontier

  1. Get questioned
  2. Write the spec
  3. Split into tickets
  4. Build one, test first
  5. Review

Every change starts from a decision you made.

The workflow · build something new

Six steps from idea to reviewed change.

Each step is a skill you can call yourself, or let /start-here call for you. Engineering is the spine; design and copy plug in before review.

  1. 01

    Grill

    /grill-me

    Questions your idea, one round at a time, until every decision is made.

    Matt Pocock
  2. 02

    Spec

    /to-spec

    Writes what you agreed into one spec in your issue tracker.

    Matt Pocock
  3. 03

    Tickets

    /to-tickets

    Splits the spec into small tickets, each with what blocks it.

    Matt Pocock
  4. 04

    Build

    /implement/tdd

    Builds one ticket at a time. A failing test comes first, then the code.

    Matt Pocock
  5. 05

    Polish

    /impeccable polish/copywriting/stop-slop

    Fixes the screen's design, writes the words, removes machine-sounding text.

    Paul Bakaus, Corey Haines, Hardik Pandya
  6. 06

    Review

    /code-review/impeccable critique

    Checks the change against the spec and the house rules before you move on.

    Matt Pocock, Paul Bakaus
Looks and reports. Runs straight away. Changes files. Waits for your go.

Improve an existing project

/improve-codebase-architecture or /impeccable critique reads the code or the screens and lists what's worth fixing. Nothing changes.

You pick the fixes, then rejoin at 03 Tickets.

Fix a bug

/diagnosing-bugs finds the cause before touching anything, then fixes it with a test that fails first.

Rejoins at 06 Review.

Write or improve copy

/copywriting writes new copy and /copy-editing tightens what's there. /stop-slop runs last.

Stands alone.

Review gates

Nothing changes your files until you say go.

Steps that only read and report run straight away. Steps that write code, edit files or create tickets stop and ask first.

Before each step runs, you get one sentence on what it does. You stay the one making decisions; Claude does the typing.

House rules

Opinions it enforces on everything it builds.

These rules sit on top of every skill, in every project. Your project's own CLAUDE.md wins where they conflict.

Design
No AI lookNo purple-to-blue gradients, glowing borders or floating card shadows.
Design
Not everything in threesVariable column spans and dense tables instead of three equal cards.
Design
A 4px gridEvery padding, margin and gap is a multiple of 4px.
Design
One bold thing per screenOne statement element. Everything else stays quiet.
Copy
Banned wordsNever "seamless", "empower", "revolutionize", "supercharge" and the rest.
Copy
Specifics over hype"Exports in 2 seconds", not "Blazing fast".

Install

Add it once. Type /start-here.

Claude app

Phone, web or desktop. Also reaches Claude Code on the same account.

  1. Open Customize → Plugins.
  2. Tap Add, then Add marketplace, and enter:
bgordon01/claude-toolkit
  1. Find toolkit under Discover and tap Add.

Claude Code

Run this inside Claude Code.

/plugin install toolkit --marketplace bgordon01/claude-toolkit

Cloud coding sessions

The Code tab and claude.ai/code start a fresh computer each time and don't load account plugins. Paste this into your environment's Setup script box once.

#!/bin/bash
curl -fsSL https://raw.githubusercontent.com/bgordon01/claude-toolkit/main/install.sh | bash || true

The plugin is still listed as toolkit while the Frontier name rolls out. Prefer a Mac install script with shorter commands? See the README.
